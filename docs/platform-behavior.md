# Platform Behavior

Where the Cumulocity platform differs from its [API docs](https://cumulocity.com/api/core/), or where the docs leave a question open that a microservice runs into. Every row names a behavior the fake platform emulates **and** a contract scenario checks it against a real tenant (`pnpm test:contract`). A test keeps this page and the scenarios in sync: every id here is verified by a scenario, and every scenario's `verifies` list points here.

Checked on a tenant of the eu-latest environment in November 2026. If a row no longer holds on your tenant, please [open an issue](https://github.com/schplitt/fake-c8y/issues).

The list and the single object answer the same.                                           |

| `delete-children-all-or-nothing`       | `DELETE .../childAssets` with references removes them.                                                                             | Nothing is removed if one id is no child (422, as for a single child); an empty `references` list answers 500 `general/internalError`.                                                                                                                                                                                                                                                                                                                                                                                                |
| `query-not-operand`                    | `not` is an operator.                                                                                                              | `not` binds tighter than `and` and `or` and takes a function (`not has(x)`), a parenthesized expression, or another `not`; a bare comparison (`not name eq 'x'`) answers 422.                                                                                                                                                                                                                                                                                                                                                         |
| `supported-series-numeric`             | `supportedSeries` lists the series of a device.                                                                                    | Only entries with a numeric `value` count; `supportedMeasurements` lists their fragments. The order is unspecified; a device without measurements answers empty lists, an unknown id 404.                                                                                                                                                                                                                                                                                                                                             |
| `supported-series-after-delete`        | Nothing.                                                                                                                           | A series stays in `supportedSeries` (and its fragment in `supportedMeasurements`) while the object has measurements with it and goes a few seconds after the last one is deleted, by id or by filter; the fake drops it at once.                                                                                                                                                                                                                                                                                                      |
| `availability-not-in-cache`            | `GET .../availability` answers the last message time.                                                                              | For objects created and fed through the REST API, and unknown ids, it answers 404 `availability/Not Found` "Availability for device with id X not found in cache"; only device connections fill that cache.                                                                                                                                                                                                                                                                                                                           |
| `latest-values-ignored`                | `withLatestValues=true` adds `c8y_LatestMeasurements`.                                                                             | The Latest Measurement feature is a preview; without it on the tenant the parameter is ignored.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `child-reference-last-updated`         | Nothing.                                                                                                                           | Adding or removing a child reference (devices, assets, or additions) sets `lastUpdated` of the parent and of the child. Updating the child leaves the parent alone.                                                                                                                                                                                                                                                                                                                                                                   |
| `delete-device-data`                   | Nothing about data of the deleted object.                                                                                          | Deleting an object deletes its external ids, measurements, events, alarms, operations, Notification 2.0 subscriptions (without audit records), and inventory assignments on it. Its parents lose the reference and keep their `lastUpdated`.                                                                                                                                                                                                                                                                                          |
| `delete-cascade`                       | A group takes its subgroups along; `cascade` deletes the devices of a device or group, `forceCascade` the hierarchy of any object. | As documented: without parameters a group takes its subgroups (recursively), not its devices and assets; with `cascade=true` a device or group takes every descendant (devices, assets, additions, recursively); `cascade` on any other object deletes only that object; `forceCascade=true` takes every descendant. Only the requested object gets an audit record.                                                                                                                                                                  |
| `create-external-ids`                  | `externalIds` assigns external ids on creation.                                                                                    | They are registered in the identity service, not stored on the object; duplicates in one request count once, a number becomes a string. A taken id answers 409 `identity/Duplicate`, a missing `type` or `externalId` 422 "post.managedObjectRepresentation.externalIds[0].type: must not be empty", a value that is no list 400; nothing is created then.                                                                                                                                                                            |
| `availability-fragments`               | `c8y_Availability` and `c8y_Connection` are set by the platform.                                                                   | Values a client sends are dropped. Creating or updating `c8y_RequiredAvailability` with a `responseInterval` above 0 sets `c8y_Availability: { lastMessage, status: AVAILABLE }` (`lastMessage` the first time only) and `c8y_Connection: { status: DISCONNECTED }`; 0 or less sets both to MAINTENANCE; no interval removes both. An interval that is a string answers 400 `Device availability/Bad Request`, a decimal 500. The platform applies this asynchronously: a read right after the write can still show the state before. |
| `managed-object-name-length`           | Nothing.                                                                                                                           | `name` and `type` take at most 1000 characters; a longer one answers 422 "post.managedObjectRepresentation.name: exceeds maximum length of 1000" (`put.` on update).                                                                                                                                                                                                                                                                                                                                                                  |
| `query-wildcards`                      | `*` in a string matches any characters.                                                                                            | A wildcard pattern supports regular expression syntax, compared without case (`h.*` matches `hxo`, `a\|b*` is an alternative), anchored by the position of the stars: `x*` starts with `x`, `*x` ends with `x`, `*x*` contains `x`. Stars inside `x*` and `*x` are dropped (`h*o*` is `^ho`); inside `*x*`, or with no star at either end, a star matches anything and the pattern is unanchored (`h*o` matches `ahoy`). A pattern with invalid syntax (`'*{*'`, a trailing backslash) answers 422.                                   |
| `query-wildcard-java-syntax`           | Nothing about the expression syntax.                                                                                               | Only some regular expression features are accepted: lone `]` and `}`, escaped punctuation (`\-`, `\_`, `\:`), `\Q...\E`, `\h`, `\A`, `\x{2D}`, POSIX classes, possessive quantifiers, atomic groups, and inline flags (`(?i)`, `(?-i)`) work; `\u0041`, `(?#...)`, `\p{IsAlphabetic}`, `(?u)`, and `\K` answer 422. The stars of `*x*` stay in the pattern, so `*?*` matches everything.                                                                                                                                              |
| `query-orderby-syntax`                 | `$orderby=field [asc\|desc]`.                                                                                                      | Fields are separated by commas; only lower-case `asc` and `desc` are accepted, a trailing comma or a third word answers 422. `$filter=` and `$orderby=` can come in any order. Objects with equal sort values come in no stable order.                                                                                                                                                                                                                                                                                                |
| `query-several-parts`                  | Nothing about repeated parts.                                                                                                      | Only the first two `$filter=`/`$orderby=` parts count and must be valid; later ones are not checked, text before the first part is ignored, and so is an empty `$filter=` at the end. Two filters: the second, but the first (and no order) once an `$orderby=` follows anywhere later. A filter and an order: both. Two orders: 422.                                                                                                                                                                                                 |
| `query-boolean-order`                  | Nothing about comparing booleans.                                                                                                  | `gt`, `ge`, `lt`, and `le` work on booleans, with `false` before `true`.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `query-ignores-filters`                | The list filters combine.                                                                                                          | With `query` or `q` the parameters `type`, `fragmentType`, `ids`, `owner`, `childAssetId`, `childDeviceId`, and `childAdditionId` are ignored; `text` and `onlyRoots` still apply. With both `query` and `q`, `query` wins and `q` (with its device-only rule) is ignored.                                                                                                                                                                                                                                                            |
| `inventory-text-search`                | `text` searches the managed objects for any of the words.                                                                          | A full-text search over id, type, name, owner, and the type and value of each external id (not fragments). Words are split at everything but letters, digits, and `_`, compared without case and diacritics, English stop words are dropped, and words are stemmed (`purging` finds `Purge`, `CMMs` does not find `CMM`, `CONT` finds nothing). Any word matches; `"..."` phrases must all occur within one field, `-word` and `-"..."` exclude, and a search with only exclusions finds nothing.                                     |
| `managed-object-body-types`            | `name`, `type`, and `owner` are strings.                                                                                           | Numbers and booleans are stored as strings (`5` becomes `"5"`); objects and arrays answer 400 `Failed to parse JSON string`, as does a child or parent collection that is no object and a `creationTime` that is no time. On a create `null` drops the field.                                                                                                                                                                                                                                                                         |
| `managed-object-server-fields`         | `id`, `creationTime`, and `lastUpdated` are read-only.                                                                             | A create may set `creationTime` (kept with its offset, like other times); `id` or `lastUpdated` in a create, and `lastUpdated` in an update, answer 422 "post.managedObjectRepresentation.lastUpdated: is not allowed here" (`put.` on update, `create.` for a child created under a parent). An unknown id answers 404.                                            |
| `managed-object-update-nothing`        | An update answers the managed object.                                                                                              | An update with nothing to change (`{}`, only ignored fields) changes nothing, not even `lastUpdated`, and answers only `self`, `id`, and empty child and parent collections.                                                                                                                                                                                                                                                                                                                                                          |
| `managed-object-body-format`           | Nothing about other content types.                                                                                                 | A create or update with a content type other than `application/json` or the managed object vendor type answers 415 without a body; an empty body answers 400, a JSON `null` 500.                                                                                                                                                                                                                                                                                                                                                      |
| `managed-object-bulk-update`           | `PUT /inventory/managedObjects` updates several objects.                                                                           | Before anything changes the ids must be given (422 `...managedObjects[1].id: is required`), distinct (422 "Duplicate ids: X"), and known (404); errors with an index carry `bulkRequest.failedIndex`. | `child-reference-content-type`         | `POST .../childDevices` takes a reference or a collection of references.                                                           | Only the content type `application/vnd.com.nsn.cumulocity.managedobjectreferencecollection+json` reads `references` (all or nothing, duplicates once, answered as `{ self, references }`; an empty or missing list adds nothing and answers 201); with any other JSON content type the body is one reference, so `{ references: [...] }` answers 422 "no child reference provided for ManagedObjectRepresentation". | `child-reference-errors`               | Nothing about invalid references.                                                                                                  | No `managedObject` answers 422 "no child reference provided for ManagedObjectRepresentation", no id 422 "no child id provided ...". | `child-reference-response`             | The answer is the reference.                                                                                                       | The child is rendered as it was before the link (an object made its own child does not list itself), its own children without names.                                                                                                                                                                                                                                                                                                                                                                                                  |
| `child-list-creation-order`            | Nothing about the order of children.                                                                                               | The managed object lists its child references in link order (a child linked again moves to the end), but the child lists (`GET .../childAssets`, also with `query`) and `bygroupid()` list the children in the order they were created. ## Paging

| Id                        | The Docs Say                                             | The Platform Does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `paging-total-pages-zero` | `totalPages` counts the pages.                           | An empty result reports `totalPages: 0` with `withTotalPages=true`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `paging-next-past-end`    | `next` links the next page.                              | Every page carries a `next` link, also the last one and pages past the end, unless `withTotalPages=true` says there is none.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `paging-page-size-422`    | `pageSize` is an integer between 1 and 2000.             | `pageSize=0` means 1, larger values are capped at 2000, and a value that is no integer answers 422.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `default-order`           | Nothing about the order without `orderBy`, or about ids. | Ids come from one counter: managed objects get a scattered two-digit prefix in front of it, so objects created in a row do not get ascending ids; events, alarms, and operations get the bare counter, measurements a 24 digit hex id. The counter is not strictly increasing either: it interleaves blocks of numbers. Inventory lists without `orderBy` (with `type`, `query`, and without `pageSize`, which gives the first 5) come in creation order, so neither ascending nor descending ids. Operations come in creation order; events, alarms, and measurements newest `time` first. Equal times are not in a stable order: events mostly the last created first, alarms the first created first, measurements in no visible order. The fake follows this with deterministic ids (option `ids: 'scattered'`) from one increasing counter, so operation ids also ascend. |

Path segments are case-sensitive (`/inventory/ManagedObjects` answers 404).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `link-parameters`                                      | Nothing.                                     | `self`, `next`, and `prev` carry the request's parameters in an order that depends on the parameter names, not on the request: the fake sorts them by a hash of the name, names with the same position in insertion order (the request's parameters, `username` last, then `pageSize`, `currentPage`, and the `withTotal*` flags). A repeated parameter keeps all its values. Values are encoded except letters, digits, and `-._~` (a space is `%20`, `*` is `%2A`). A negative `currentPage` is echoed in `self`, and `next` is that plus one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Reason phrase (core platform seen, services to verify) | Nothing.                                     | Every answer carries the standard reason phrase of its status as `statusText` (`404 Not Found`), as a server sends it over HTTP/1.1 and Node's `fetch` reports it. Seen on the core platform over HTTPS (`404 Not Found` for an unknown role name). Still to verify per microservice: a microservice may send no phrase, and the microservice-internal URL may differ. The fake adds it to every answer without one, service answers included.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
